# Морской бой

Написать распределенное клиент-серверное приложение, исполь-
зуя указанную технологию распределенной объектной обработки.
Приложение реализует игру «Морской бой» со следующими прави-
лами:
– в игре присутствует один игрок, который задает размеры поля и
количество целей на поле;
– серверная часть размещает цели на поле случайным образом;
– игрок совершает «выстрелы» по ячейкам поля, получая инфор-
мацию о пораженных целях и промахах;
– количество «выстрелов» игрока ограничено;
– игра заканчивается, когда игрок совершил все выстрелы или
поразил все цели.
Технология servlets (JSP, JSF).

1	Постановка задачи (Игра «Морской бой», технология Servlets)
1.1	Описание системы
Система представляет собой однопользовательскую веб-версию игры «Морской бой», реализованную по технологии сервлетов. Игрок через веб-интерфейс задает параметры партии: размеры поля, количество целей и доступное количество выстрелов. Сервер случайным образом размещает на поле заданное количество целей (одноклеточных кораблей). Игрок совершает выстрелы, указывая координаты. Сервер обрабатывает каждый выстрел, фиксируя попадания или промахи, и возвращает обновленное состояние поля. Игра завершается победой при уничтожении всех целей или поражением при исчерпании всех выстрелов.
1.2	Функциональность системы
1.2.1	Функции сервера
1)	Управление игровыми сессиями:
      	создание новой игровой сессии при запуске игры;
      	хранение состояния игры для каждого игрока;
      	завершение и удаление сессии при сбросе игры.
2)	Валидация входных параметров:
      	проверка допустимости размеров поля (от 10 до 20);
      	проверка количества целей (целое положительное число не более ⌈N/2⌉×⌈M/2⌉);
      	отклонение некорректных запросов с выдачей сообщения об ошибке.
3)	Формирование игрового поля:
      	создание структуры поля заданного размера;
      	случайное размещение заданного количества одноклеточных целей;
      	гарантия отсутствия пересечений целей.
4)	Обработка выстрелов:
      	получение координат из HTTP-запроса;
      	проверка корректности координат (в пределах поля);
      	проверка на повторный выстрел в ту же клетку;
      	определение результата: «Попадание» или «Промах»;
      	уменьшение счётчика оставшихся выстрелов;
      	фиксация результата в состоянии игры.
5)	Контроль завершения игры:
      	проверка уничтожения всех целей;
      	проверка исчерпания доступных выстрелов;
      	установка статуса «Победа» или «Поражение»;
      	блокировка обработки дальнейших выстрелов.
6)	Предоставление состояния клиенту:
      	формирование HTML-страницы (JSP/JSF) с игровым полем;
      	отображение результатов выстрелов (отметки на поле);
      	отображение количества оставшихся выстрелов и уничтоженных целей;
      	вывод итогового сообщения о завершении игры.
7)	Обеспечение многопоточности:
      	корректная обработка параллельных запросов от множества пользователей с изоляцией их игровых сессий.
      1.2.2	Функции клиентской части
1)	Инициализация игры:
      	ввод параметров новой игры (строки, столбцы, цели, выстрелы);
      	отправка параметров на сервер для создания сессии.
2)	Пользовательский интерфейс:
      	отображение игрового поля в виде сетки;
      	отображение результатов выстрелов (например, «X» для попадания, «•» для промаха);
      	отображение текущего счета (оставшиеся выстрелы, уничтоженные цели).
3)	Передача игровых действий:
      	ввод координат выстрела (строка и столбец);
      	отправка координат на сервер;
      	получение и отображение обновленного состояния от сервера.
4)	Управление пользовательским сценарием:
      	блокировка интерфейса для ввода выстрелов после завершения игры;
      	предоставление кнопки для сброса игры и возврата к настройкам параметров.
      1.3	Сущности предметной области
      	Игровая сессия. Объект, хранящий состояние конкретной игры. Содержит размеры поля (N, M), координаты целей, информацию о произведенных выстрелах, количество оставшихся выстрелов и количество уничтоженных целей;
      	Игровое поле. Двумерная сетка размером N x M. Каждая ячейка может быть: пустой и необстрелянной, пустой с промахом, содержать целую цель или уничтоженную цель. Игроку видно только два последних состояния;
      	Цель. Атомарная сущность, занимающая ровно одну клетку поля. При попадании считается уничтоженной;
      	Игрок. Пользователь, взаимодействующий с системой через веб-браузер. Идентифицируется и изолируется посредством механизма сессий;
      	Результат выстрела. Ответ сервера на действие игрока. Содержит текстовый результат («Попадание», «Промах» или ошибка), обновленное состояние поля и текущую статистику;
      	Координата. Пара целых чисел (строка, столбец) для идентификации конкретной ячейки на поле.

1.4	Ограничения и допущения
	Правила игры. Игра является однопользовательской. Корабли (цели) всегда одноклеточные. Корабли не должны касаться друг друга ни сторонами, ни углами (правило "касания" строго соблюдается);
	Размеры поля: целые числа N и M в диапазоне [10; 20];
	Количество целей: любое целое число от 1 до ⌈N/2⌉ × ⌈M/2⌉;
	Количество выстрелов: целое положительное число, не менее количества целей, не более количества клеток;
	Выстрелы: повторный выстрел в одну и ту же клетку запрещен и считается ошибкой;
	Хранение данных. Состояние игры хранится только в памяти сервера в рамках HTTP-сессии. После завершения или тайм-аута сессии данные теряются. Постоянное хранение (например, в базе данных) не предусмотрено;
	Сетевое взаимодействие. Обмен данными осуществляется исключительно по протоколу HTTP. Сервер работает в контейнере сервлетов, который управляет параллельными запросами и жизненным циклом сессий.
