# Техническое задание

## Разработка веб-приложения «Морской бой» на основе технологии Servlets

## 1. Общая постановка задачи

Необходимо разработать распределённое клиент-серверное веб-приложение, реализующее игру «Морской бой».
Приложение должно быть построено с использованием технологии **Java Servlets** и средств отображения **JSP или JSF**.

Игра является **однопользовательской**. Пользователь взаимодействует с системой через веб-интерфейс, задаёт параметры игры и выполняет выстрелы по игровому полю.

Серверная часть отвечает за генерацию игрового поля, обработку действий игрока и управление игровой сессией.

Игра завершается в одном из двух случаев:

* игрок уничтожил все цели (победа);
* игрок исчерпал доступное количество выстрелов (поражение).

---

# 2. Назначение системы

Разрабатываемая система предназначена для реализации веб-версии игры «Морской бой», в которой:

* пользователь задаёт параметры игровой партии;
* сервер генерирует игровое поле со случайным размещением целей;
* пользователь выполняет выстрелы по координатам;
* система отображает результаты выстрелов и состояние игры.

Система должна работать через веб-браузер и не требовать установки дополнительного программного обеспечения на стороне пользователя.

---

# 3. Архитектура системы

Система реализуется по **клиент-серверной архитектуре** и состоит из двух основных компонентов:

### Клиентская часть

Реализуется в виде веб-интерфейса, доступного через браузер.
Отвечает за:

* ввод параметров игры;
* отображение игрового поля;
* отправку действий пользователя на сервер;
* отображение результатов игры.

### Серверная часть

Реализуется с использованием **Java Servlets** и выполняет:

* обработку HTTP-запросов;
* управление игровыми сессиями;
* генерацию и хранение игрового поля;
* обработку выстрелов;
* формирование HTML-ответов.

---

# 4. Функциональные требования

## 4.1 Функции серверной части

### 4.1.1 Управление игровыми сессиями

Сервер должен обеспечивать:

* создание новой игровой сессии при запуске игры;
* хранение состояния игры в рамках HTTP-сессии пользователя;
* удаление или сброс сессии при завершении игры или перезапуске.

---

### 4.1.2 Валидация входных данных

Сервер должен проверять корректность параметров игры:

* размеры поля должны находиться в диапазоне **10–20**;
* количество целей должно быть положительным числом и не превышать
  **⌈N/2⌉ × ⌈M/2⌉**;
* количество выстрелов должно быть положительным числом.

При обнаружении ошибок сервер должен возвращать сообщение о некорректных данных.

---

### 4.1.3 Формирование игрового поля

Сервер выполняет следующие действия:

* создание двумерного игрового поля размером **N × M**;
* случайное размещение заданного количества целей;
* обеспечение отсутствия пересечений целей;
* соблюдение правила, при котором цели не касаются друг друга ни сторонами, ни углами.

---

### 4.1.4 Обработка выстрелов

При получении координат выстрела сервер должен:

* проверить корректность координат;
* проверить, выполнялся ли ранее выстрел в данную клетку;
* определить результат выстрела:

      * попадание;
      * промах;
* уменьшить количество оставшихся выстрелов;
* сохранить результат выстрела в состоянии игры.

---

### 4.1.5 Контроль завершения игры

После каждого выстрела сервер должен проверять:

* уничтожены ли все цели;
* закончились ли доступные выстрелы.

В зависимости от результата игра получает статус:

* **Победа** — уничтожены все цели;
* **Поражение** — выстрелы закончились.

После завершения игры дальнейшие выстрелы должны быть заблокированы.

---

### 4.1.6 Формирование ответа клиенту

Сервер должен формировать HTML-страницу, содержащую:

* игровое поле;
* результаты выстрелов;
* количество оставшихся выстрелов;
* количество уничтоженных целей;
* итоговое сообщение о победе или поражении.

Отображение реализуется с использованием **JSP или JSF**.

---

### 4.1.7 Обработка параллельных запросов

Система должна корректно обрабатывать запросы от нескольких пользователей одновременно.
Каждая игровая сессия должна быть изолирована от других пользователей.

---

# 5. Функции клиентской части

## 5.1 Инициализация игры

Клиент должен обеспечивать:

* ввод параметров новой игры:

      * количество строк;
      * количество столбцов;
      * количество целей;
      * количество выстрелов;
* отправку параметров на сервер для создания игровой сессии.

---

## 5.2 Пользовательский интерфейс

Интерфейс должен обеспечивать:

* отображение игрового поля в виде сетки;
* отображение результатов выстрелов:

      * **X** — попадание;
      * **•** — промах;
* отображение текущей статистики игры:

      * оставшиеся выстрелы;
      * уничтоженные цели.

---

## 5.3 Передача игровых действий

Клиент должен позволять:

* ввод координат выстрела;
* отправку координат на сервер;
* получение обновленного состояния игры.

---

## 5.4 Управление игровым сценарием

После завершения игры интерфейс должен:

* блокировать возможность новых выстрелов;
* отображать результат игры;
* предоставлять кнопку **«Новая игра»** для запуска новой партии.

---

# 6. Сущности предметной области

## Игровая сессия

Объект, содержащий состояние текущей игры:

* размеры поля;
* координаты целей;
* список произведенных выстрелов;
* количество оставшихся выстрелов;
* количество уничтоженных целей.

---

## Игровое поле

Двумерная сетка размером **N × M**.
Каждая клетка может находиться в одном из состояний:

* пустая и необстрелянная;
* пустая с промахом;
* содержит цель;
* содержит уничтоженную цель.

Игроку отображаются только результаты выстрелов.

---

## Цель

Одноклеточный объект, размещённый на поле.
При попадании цель считается уничтоженной.

---

## Игрок

Пользователь системы, взаимодействующий с приложением через браузер.
Идентификация выполняется через механизм HTTP-сессий.

---

## Результат выстрела

Ответ сервера на действие игрока, включающий:

* результат выстрела (попадание или промах);
* обновлённое состояние игрового поля;
* статистику текущей игры.

---

## Координата

Пара целых чисел:

* номер строки;
* номер столбца.

Используется для идентификации клетки игрового поля.

---

# 7. Ограничения и допущения

### Правила игры

* игра является **однопользовательской**;
* все цели занимают **одну клетку**;
* цели **не должны касаться друг друга** ни сторонами, ни углами.

---

### Ограничения параметров игры

Размеры поля:

```
10 ≤ N ≤ 20
10 ≤ M ≤ 20
```

Количество целей:

```
1 ≤ targets ≤ ⌈N/2⌉ × ⌈M/2⌉
```

Количество выстрелов:

```
targets ≤ shots ≤ N × M
```

---

### Ограничения на выстрелы

* повторный выстрел в одну клетку запрещён;
* при попытке повторного выстрела сервер возвращает ошибку.

---

### Хранение данных

Состояние игры хранится:

* только в **оперативной памяти сервера**;
* внутри **HTTP-сессии пользователя**.

После завершения или тайм-аута сессии данные удаляются.

Использование базы данных **не предусмотрено**.

---

### Сетевое взаимодействие

Взаимодействие клиента и сервера осуществляется по протоколу:

```
HTTP
```

Сервер работает внутри **контейнера сервлетов**, который управляет:

* жизненным циклом сервлетов;
* обработкой HTTP-запросов;
* управлением пользовательскими сессиями.
